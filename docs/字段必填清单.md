# jshERP 单据字段：到底哪些必须填？

> 结论来自三处交叉验证（非猜测）：
> 1. 数据库 DDL（`jshERP-boot/docs/jsh_erp.sql`）：`jsh_depot_head` / `jsh_depot_item` 除主键外几乎全部可 NULL
> 2. 前端表单校验（`jshERP-web/src/views/bill/modules/*Modal.vue` 的 `validatorRules`）—— 这是操作员实际被强制填的
> 3. 实测写库成功（采购入库 `00000000675`，仅提供 4 类信息）

---

## 一、一句话结论

**操作员/AI 真正需要提供的只有 4 样：谁、什么货、多少、多少钱。**

其余 20+ 字段要么系统自动生成，要么有安全默认值，要么是高级功能（用不到就别填）。

---

## 二、字段三级分类

### 🔴 L1 必填（用户必须提供，无法推断）

| 字段 | 说明 | 例 |
|------|------|-----|
| `organId` | 往来单位 = 供应商/客户 | 美宜佳 |
| `barCode` + `materialId` | 商品（明细行） | 可乐 |
| `operNumber` | 数量（明细行） | 3 |
| `unitPrice` | 单价（明细行）※严格说非必填，但不填金额为 0，业务无意义 | 3.5 |

> 「其他入库/出库/调拨」连 `organId` 都不必填（前端只要求 `type`）。

### 🟡 L2 系统自动生成（用户永远不用管）

| 字段 | 自动来源 |
|------|---------|
| `number` 单据编号 | `/sequence/buildNumber?type=前缀`，或按日期自增 |
| `operTime` 单据日期 | 当前时间 |
| `type` / `subType` | 由业务类型推导（采购入库 = 入库/采购） |
| `totalPrice` / `allPrice` | 数量 × 单价 自动算 |
| `depotId` 仓库 | 无指定时取默认仓（入库→原料仓，出库→成品仓） |
| `tenantId` | 后端按 token 注入，**传了会报错** |
| `creator` / `createTime` | 后端自动 |
| `barCode` | 新建商品时自动建 `BC<materialId>` |

### 🟢 L3 可选（默认值够用，绝大多数场景不填）

| 字段 | 默认 | 什么时候才需要填 |
|------|------|-----------------|
| `accountId` 结算账户 | 25（中国银行对公） | 有多个银行账户要区分时 |
| `changeAmount` 本次实付/实收 | = 总金额（全款） | **赊账**：只付一部分，填实付额，差额自动进 `debt` |
| `payType` 付款方式 | 现付 / 现收 | 记账、预付款 |
| `status` 审核状态 | `"1"` 已审核（库存立即变动） | 想先存草稿填 `"0"` |
| `remark` 备注 | 空 | 需要备注时 |
| `discount` / `discountMoney` | 空 | 有整单折扣 |
| `otherMoney` | 空 | 运费等附加费用 |
| `salesMan` 销售员 | 空 | 需要业绩统计 |
| `deposit` 订金 | 空 | 订单类单据收订金 |
| `accountIdList` + `accountMoneyList` | 空 | 一笔钱拆多个账户付 |
| `snList` 序列号 | 空 | 商品开启了序列号管理 |
| `batchNumber` 批号 / `expirationDate` | 空 | 商品开启了批次管理（食品药品） |
| `taxRate` / `taxMoney` | 空 | 需要单独核算税额 |
| `anotherDepotId` | — | **仅调拨单必填**：调入方仓库 |
| `linkNumber` 关联单号 | 空 | 由订单转入库单时 |

## 三、各单据类型的前端强制校验（实测提取）

| 单据 | 表头强制 | 明细强制 |
|------|---------|---------|
| 采购入库 | operTime, number, organId, accountId, changeAmount | barCode, operNumber |
| 销售出库 | operTime, number, organId, accountId, changeAmount | barCode, operNumber |
| 采购退货 | operTime, number, organId, accountId | barCode, operNumber |
| 销售退货 | operTime, number, organId, accountId | barCode, operNumber |
| 其他入库/出库 | operTime, number, type | barCode, operNumber |
| 调拨出库 | operTime, number, type | barCode, operNumber |
| 采购/销售订单 | operTime, number, organId | barCode, operNumber |
| 零售出库 | operTime, number, accountId | barCode, operNumber |

> 注意：表头里 operTime / number / accountId / changeAmount 虽被前端标"必填"，但**都能由程序自动生成**——这正是我们的壳子替用户消化掉的部分。

## 四、赊账怎么表达（唯一需要理解的业务概念）

```
totalPrice   = 100   总金额（自动算）
changeAmount = 30    这次实际付了 30
debt         = 70    自动 = 100 - 30，欠款
```

- 全款付清：`changeAmount = totalPrice`（默认行为）
- 挂账不付：`changeAmount = 0`
- 后续还款：另建**付款单** `/accountHead/addAccountHeadAndDetail`，用 `billNo` 关联原单

⚠️ jshERP 原设计：**收付款单不会自动改账户余额字段**，采购单与付款单不联动。

## 五、易踩的坑

| 坑 | 后果 | 正确做法 |
|----|------|---------|
| body 传 `tenantId` | SQL 报 `tenant_id specified twice` | 绝不传，后端按 token 注入 |
| 商品没建条码就建单 | `Value for barCode cannot be null` | 先 `POST /materialsExtend/add` |
| `rows.barCode` 取 material 主表 | 500 未知异常 | 必须取 materialsExtend 表的 barCode |
| 列表查询平铺传 type | `code:300` | 包进 `search={"type":...}` JSON 参数 |
| **查单据不传 `subType`** | **`code:300` 数据查询异常** | **`subType` 必传**！后端 `DepotHeadService.getBillCategory()` 第1798行对 subType 直接 `.equals()`，为 null 时 NullPointerException。要查全部就遍历所有 subType 合并（`erp.all_bills()` 已封装） |
| `materialsExtend/getDetailList` 用 search | 500 | 这个接口反而要**平铺** `?materialId=xxx` |
| 收付款单 `billNo` 放 rows | 500 | 放 info 主表 |
| `materialCategory/getAllList` 不带参数 | 500 | 必须带 `?parentId=0` |
| `status` 填 0 | 库存不变动 | 要立即生效填 `"1"` |
