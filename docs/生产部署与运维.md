## 2. 目录布局

| 路径 | 作用 |
|---|---|
| `/opt/talk2stock` | **生产副本**（systemd 直接跑这里的 `app/server.py`），也是 git 仓库，`main` 与 GitHub 同步 |
| `/opt/talk2stock/app/.env` | 全部密钥与运行开关（0600，`.gitignore` 排除，**不进仓库**） |
| `/opt/talk2stock/app/config.json` | 本机配置（ERP 地址、模型档案、默认仓库/账户），含网关地址，`.gitignore` 排除 |
| `/opt/talk2stock/app/data/` | `audit.jsonl`（写入与被拒审计）、`oplog.jsonl`（/api 耗时与结果）、`usage.jsonl`（token 分账）、`used_tokens.jsonl` |
| `/opt/talk2stock/backups/` | 数据库快照（`seed-backup-*.sql`，演示数据重置前自动生成） |
| `/opt/talk2stock/jshERP-latest/deploy/` | ERP 的 docker compose 编排（相对路径挂载 `../jshERP-boot/docs/jsh_erp.sql`，**整个目录必须整体移动**） |
| `/root/projects/talk2stock` | 开发副本（另一份独立 git 仓库，用于改代码/写文档）；改完必须 `git push` 再在 `/opt/talk2stock` `git pull` |

> 两份副本不是同一个工作区：生产改代码 → 重启服务；开发改代码 → push → 生产 pull → 重启。
> 曾经踩过的坑：以为改了一份两边都变，实际只改了开发副本，线上没生效。

## 3. 配置（键名在此，值只在 `.env` 里）

`app/.env` 当前包含（值不外发）：

| 键 | 用途 |
|---|---|
| `T2S_ERP_BASE` | `http://localhost:9999/jshERP-boot` |
| `T2S_ERP_USER` / `T2S_ERP_PASS` | 服务端调 ERP 用的账号（密码明文，服务端登录时做 MD5） |
| `T2S_KEY_WORKBUDDY` / `T2S_BASE_WORKBUDDY` | 主用模型档案的 Key 与自建网关地址 |
| `T2S_KEY_MODA` | ModelScope 备用档案（Qwen3.8-Flash-Next）Key |
| `T2S_REQUIRE_AUTH=1` | 所有 `/api` 必须登录（**公网实例必须为 1**） |
| `T2S_DEMO_PASS` | 管理员后备通道口令（ERP 挂了也能进设置页）；本实例已改为自定义口令，**默认值 `talk2stock` 等同公开后门，新部署必须更换** |
| `T2S_ADMINS` | 额外管理员名单（逗号分隔 ERP 登录名）；ERP 角色为管理员的本来就算管理员 |
| `T2S_SESSION_TTL_DAYS` | 登录会话有效期（默认 30 天） |

模型档案在 `app/config.json` 的 `llm.profiles`：当前启用 `workbuddy`（`http://localhost:7863/v1`，
`global:hy4free`，`merge_system` + `insecure` + `X-Prompt-Mode: passthrough`），备用 `moda`。
密钥永远在 `.env` 的 `T2S_KEY_<档案名大写>`，`config.json` 里没有密钥。

## 4. 账号与权限

| 账号 | 用途 | 说明 |
|---|---|---|
| ERP `admin` / 见 `.env` | 管理员（ERP `ismanager`/角色为管理员 → Talk2Stock 管理员） | 可改共享模型档案、ERP 连接，看用量分账 |
| ERP `jsh` | 系统自带租户所有者（`isystem=1`） | 保留，不对业务开放 |
| 普通 ERP 账号 | 录单员/成员 | 只能录单、问答、配自己的私有模型档案；`/api/config/*` 返回 403 |

登录链路：前端提交 ERP 登录名+密码 → 服务端转发 ERP `/user/login`（MD5 在服务端做，密码不落盘）
→ 校验通过后签发 HMAC 无状态会话（默认 30 天，重启不失效）。连续失败 5 次锁 60 秒。

> 初始化 SQL 自带的默认口令是公开值（`123456`），本实例已改。**新增账号后同样要改密。**

## 5. 日常命令

```bash
# 状态 / 重启 / 停止
systemctl status talk2stock
systemctl restart talk2stock          # 改了 app/*.py 必须重启；app/web/* 静态文件改动免重启

# 日志
tail -f /opt/logs/talk2stock.log

# 健康检查（401 + need_auth=true = 服务活着且鉴权生效）
curl -s -o /dev/null -w '%{http_code}\n' localhost:8090/
curl -s localhost:8090/api/health

# ERP 容器
cd /opt/talk2stock/jshERP-latest/deploy
docker compose ps
docker compose logs --tail=80 erp-backend
docker exec erp-backend date          # 必须是 CST，否则「今天」的单据查不到

# 应用层自检 / 端到端验证
cd /opt/talk2stock && python3 app/selfcheck.py
bash verify-local.sh

# 单元测试（236 项，零依赖，约 0.4s）
python3 -m unittest discover -s tests -q
```

## 6. 备份与恢复

```bash
cd /opt/talk2stock
# 业务库（在线一致性快照）
docker exec erp-mysql mysqldump -uroot -p"$MYSQL_PWD_ROOT" --single-transaction jsh_erp \
  > backups/jsh_erp-$(date +%F).sql
# 留痕 + 配置（含密钥，权限自行收紧）
tar czf backups/t2s-state-$(date +%F).tar.gz app/data app/config.json app/.env
# 恢复
docker exec -i erp-mysql mysql -uroot -p"$MYSQL_PWD_ROOT" jsh_erp < backups/jsh_erp-YYYY-MM-DD.sql
```

演示数据重置（**只对演示库**，会清场重建 7 往来单位 / 7 商品 / 9 张单）：

```bash
python3 eval/seed_demo.py --yes     # 自带备份 → 清场 → 重建，幂等
```

生产业务库**绝不**跑 `seed_demo.py`；也不要把测试产物写进 `app/data/`（审计/用量是真实数据）。

## 8. 排障速查

| 现象 | 处理 |
|---|---|
| 8090 打不开 / 转圈 / curl 返回 `000` | 进程僵死：`lsof -nP -iTCP:8090 -sTCP:LISTEN -t \| xargs kill -9` 后 `systemctl restart talk2stock` |
| 页面能开但所有接口 401 | 正常（未登录）。`T2S_REQUIRE_AUTH=1` 时需 ERP 账号登录；管理员可用 `T2S_DEMO_PASS` 走后备通道 |
| 登录提示「账号或密码不对」 | 本实例 ERP 对密码错误/账号不存在返回同一句 `user password error`（HTTP 200 + code 200，错误在 `data.msgTip`）；从文案分不出是否被锁，连续失败 3~4 次就等 30 分钟 |
| 录单成功但 ERP「今天」查不到 | 时区：`docker exec erp-backend date` 应为 CST |
| AI 解析报 400 / `response_format` 不支持 | `llm.py` 会自动降级；仍失败多为 Base URL 少 `/v1` 或模型名不对。设置页「测试连接」先验证 |
| 推理模型反复「解析失败」 | 决策输出封顶太小或 `reasoning_effort` 太高：档案里设 `low`，`agent_max_tokens` 2000 |
| 欠款/单据数字对不上 | 单类单据超约 200 张的已知边界（P4），见 `docs/failure-cases.md` |
| 公网端口不通但本机 curl 通 | 云控制台安全组未放行；本机 ufw 只放行 22/80/443/8080/8090/28465/28466/7863/5000 |
