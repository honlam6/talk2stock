# Talk2Stock 交互流程设计与边界情况清单

> 定位：Talk2Stock 是一个**对话式 ERP 录单智能体（Conversational ERP Agent）**，
> 不是给原系统"套壳"。它有自己的感知—决策—行动—确认回路：
> 理解口语 → 匹配主数据 → 生成带来历标注的草稿 → 人确认 → 通过官方接口写入 → 留痕。
> 本文档回答两个评审必问的问题：**流程是怎么设计的？边界情况想到了哪些、分别在哪一层拦住？**

---

## 一、核心流程（一条单据的生命周期）

```
 用户说一句话（AI 页）或填表（表单页）
        │
        ▼
 ┌─ 感知层 ──────────────────────────────────────────────┐
 │ LLM 解析：意图分类(6 类业务) → 字段抽取 → 强制 JSON     │
 │ 防幻觉约束：只许抽 4 类信息，编号/金额合计/ID 禁止编造   │
 │ 输出自检：normalize() 清洗 + 问题列表                   │
 └──────────────┬────────────────────────────────────────┘
                ▼
 ┌─ 决策层（resolve，只读不写）───────────────────────────┐
 │ 主数据匹配：精确 → 归一 → 包含，三级匹配                │
 │ 每个字段标出来历：已有 / 匹配→X / 将新建 / 系统默认     │
 │ 风险检查：缺单价、库存不足将负库、缺供应商/数量          │
 │ 签发一次性确认令牌（与草稿内容哈希绑定，30 分钟过期）    │
 └──────────────┬────────────────────────────────────────┘
                ▼
 ┌─ 确认卡（人机接口的心脏）──────────────────────────────┐
 │ AI 置信度 + note（信息不全时明说缺什么）                 │
 │ 将新建档案清单（杜绝"写完才发现建了一堆档"）             │
 │ 单价为 0 高亮、负库存橙色提醒、错误红字并禁用提交按钮    │
 └──────┬─────────────────────────────────┬──────────────┘
   点「确认写入」                     点「再改改」
        ▼                                 ▼
 ┌─ 行动层（commit）──────────────┐   关闭弹层，改完重新预览
 │ 闸门校验：无令牌/过期/草稿被改   │  （旧令牌自动作废）
 │ → 一律拒绝并记审计              │
 │ 通过 → 补建主数据 → 官方 REST   │
 │ 建单 → 审计日志（原话/模型/      │
 │ 提示词版本/diff/结果）           │
 │ 用户改过的字段 → 回归测试集      │
 └────────────────────────────────┘
```

三条设计不变量（写入闸门的自证点）：
1. **没有人工确认事件的写入请求一律拒绝**——服务端强制，不是 UI 约定（见 `core/gate.py`）。
2. **只通过 jshERP 官方 REST API 写入**——任何环节不碰数据库表。
3. **每张写进去的单都留一条审计记录**——原话、模型、提示词版本、改动 diff、结果。

## 二、边界情况清单（按拦截层分类）

设计原则：**错误拦得越早成本越低**。每类边界标注它被哪一层拦住、用户看到什么。

### A. 理解层（LLM 解析）

| # | 边界情况 | 处理方式 | 用户看到 |
|---|---|---|---|
| A1 | 口语数字「三块五」「三十瓶」 | `_to_num` 中文金额解析 + LLM 抽取，双重处理 | 正常数值 |
| A2 | 「3瓶可乐」数量混进商品名 | prompt 约束 + `_clean_name` 正则剥离 | name=可乐，qty=3 |
| A9 | 商品名自带型号/规格数字（M8螺丝、6号电池、2.5平方电线、304不锈钢管） | prompt v4 规则：数量/单价不进名字，但型号规格必须完整保留；主数据名单带型号整串照抄 | name=M8螺丝（不是"螺丝"） |
| A10 | 一句话多规格「4分和6分的PPR管各20根」 | prompt v4 规则：拆成多行明细，每行一个完整规格名、各自单价 | 两行明细 |
| A11 | 「欠80」（欠款语义） | 模型按 总额−欠款 算实付（`pay_amount`），ERP 自动算欠款 | 实付 120 / 欠 80 |
| A12 | 相对日期超集「上个月15号」「上周」 | 注入当前日期 + 模型换算（实测上个月15号→正确年月日）；说不清的压 low | 绝对日期 + ⚠ 提示 |
| A13 | 约数「十来个」「差不多20」 | 按整数入账 + confidence low + note 说明是约数 | ⚠ AI 提示：约数已按 X 录入 |
| A14 | 数字黏名词的商品名「6号电池」「304不锈钢管」 | `_clean_name` 只剥「数字+量词」（3瓶可乐），数字直接黏名词是型号规格一律保留 | name 完整保留 |
| A15 | 输入超长（整段聊天记录贴进来） | 服务端 1000 字上限 + 提示「多笔用；分段，装不下分两次录」（v5） | 友好错误，不浪费一次解析 |
| A8 | 一句话里混多笔业务（v5 起支持多单） | **按业务边界拆成 bills[] 多张草稿**（分号/句号/换往来单位/换方向），字段绝不跨单搬用；每单独立 confidence/note，批量预览层逐单确认（见《多单批量与多模态录入设计》） | 批量确认卡 + 逐单状态徽章 |
| A3 | 「从/给/跟」等介词黏在单位名上 | `_clean_party` 剥前缀后缀 | 干净名称 |
| A4 | 网关丢弃 system 角色（自建网关实测会发生） | 档案级 `merge_system` 开关，把规则并入首条 user 消息 | 无感 |
| A5 | 端点不支持 `response_format` / 流式挂起 | 三级降级：流式+JSON → 流式 → 非流式 | 无感 |
| A6 | 自签证书 / IP 直连网关 | 档案级 `insecure` 开关 | 无感 |
| A7 | 返回非 JSON / 代码块包裹 | 剥 markdown + 平衡大括号提取；仍失败则报错重试 | 「解析失败」提示 |

### B. 决策层（主数据匹配 / 预览）

| # | 边界情况 | 处理方式 | 用户看到 |
|---|---|---|---|
| B1 | **原话没说单价**（实测最高频） | resolve 标记 `price_missing`，预览警告 + 单价列橙色高亮「单价?」 | ⚠ 第X行单价为 0：若非赠品请补单价 |
| B2 | 没说数量 / 数量为 0 | validate 硬拦截 | 红字「第X行数量必须大于 0」，按钮禁用 |
| B3 | 没说供应商/客户 | validate 硬拦截 | 红字「缺少供应商名称」 |
| B4 | 供应商/商品档案不存在 | 不阻塞：列入「将新建」清单，确认后一并创建 | 「以下资料将自动建好」黄色卡 |
| B5 | 名字相似但不完全相同 | 三级模糊匹配，标「匹配→X」 | 可人工否决的匹配提示 |
| B6 | 没说仓库 | 按 UI 配置取默认仓（入→原料仓 / 出→成品仓），预览标明 | 确认卡显示实际入库 |
| B7 | 出库后库存为负 | 查实时库存，橙色警告（jshERP 允许负库存是原设计，只提醒不拦截） | 「当前库存 0，将产生负库存」 |
| B8 | 没说日期 | 默认当前时间，确认卡显示实际写入时间 | 可见、可改 |
| B9 | 「先付了500」「欠一半」 | `pay_amount` 抽取，ERP 按实付建单自动算欠款 | 确认卡显示实付 |
| B10 | **一个配件多个同名档案（规格不同）**（issue #1 场景） | `find_material` 返回 `ambiguous`，绝不静默挑第一个；预览警告 + top 候选（带型号）让人点选 | ⚠「有多个同名档案，请点选对应规格」+「是指：螺丝 · M8×20 / 螺丝 · M10×30」 |
| B11 | 规格放在档案的型号/标准字段，名字不带 | 名字+型号+标准**合成串**匹配（括号/×x/大小写归一）：「螺丝M8」→ 档案「螺丝 / M8×20」 | 「匹配→螺丝 M8×20」 |
| B12 | 点选候选 / 补全里选中档案后 | `items[].material_id` 直达档案（闸门令牌覆盖该字段），写入不再靠名字猜；手改名字即解除锁定 | 「匹配→螺丝 M8×20」绿色标签 |
| B13 | 同名多档案但没点选就点确认 | commit 预检在任何写入前拦截（不产生半截单/孤儿档案） | 「请回预览点选对应规格」 |
| B14 | 直接输**条码**（扫码枪/单据抄录，EAN-13 或自建 BC\<id\>） | 3-20 位含数字串先按 `mBarCode` 精确对档案；无命中再走名字匹配 | 「匹配→螺丝 M8×20」 |
| B15 | 多轮修正（点选规格后说「改成20盒」） | 服务端把点选的 `material_id` 按商品名带回新草稿——改数不重选；换商品名则不带 | 修正后仍「匹配→螺丝 M8×20」 |
| B16 | 供应商/客户同名多档案 | 与商品同规则：`ambiguous` + 候选点选 + commit 写前预检 | ⚠「有多个同名档案，请点选」 |

### C. 写入层（闸门 / 原子性）

| # | 边界情况 | 处理方式 | 用户看到 |
|---|---|---|---|
| C1 | **绕过 UI 直接 POST /api/commit** | 服务端闸门：无令牌拒绝 + 审计记录 | `need_confirm` 拒绝 |
| C2 | 伪造 / 过期令牌（30 分钟） | 同上 | 同上 |
| C3 | **确认后篡改草稿再提交**（curl 复放攻击） | 令牌与草稿内容 sha256 绑定，内容不符拒绝且令牌作废 | 「草稿在确认后被改动」 |
| C4 | 双击确认按钮 / 令牌重放 | 令牌一次性，用后即焚 | 第二次被拒 |
| C5 | 主数据补建成功但建单失败 | `created` 列表返回实际建了什么；档案不是垃圾——下次录单直接复用 | 提示已建档案，可继续用 |
| C6 | ERP 容器没起 / 网络断 | 友好中文提示（不抛栈） | 「无法连接 ERP 服务…」 |
| C7 | 必填字段缺失打到 ERP 才发现 | 上游已用 validate 前置拦截；ERP 500 时提示看日志 | 「写入失败 + 原因」 |

### D. 部署 / 配置层

| # | 边界情况 | 处理方式 |
|---|---|---|
| D1 | API Key 泄露 | 密钥只存 `.env`（gitignore），`config.json` 永不含密钥，页面回显脱敏 |
| D2 | 服务暴露公网被任意写库 | `T2S_REQUIRE_AUTH=1` + 修改 `T2S_DEMO_PASS`；闸门本身也挡未确认写入 |
| D3 | JVM 时区 UTC 导致单据"消失" | 容器 `TZ: Asia/Shanghai`（已踩坑并修复，见部署验证报告 §七） |
| D4 | 8090 进程僵死占端口 | `start-all.sh` 启动前清理占用进程并二次确认 |
| D5 | 多模型切换混乱 | 档案化配置，页面即配/切/测，key 按 `T2S_KEY_<档案>` 隔离 |
| D6 | 厂商推理强度叫法不一（OpenAI 系 `reasoning_effort` / Qwen 只有开关 / Claude 系 `thinking` 配置） | 档案级双旋钮：`reasoning_effort`（minimal/low/medium/high 事实标准）+ `extra_body` 厂商私有参数原样透传；问一问决策步自动 low（与 `agent_max_tokens` 封顶互补）；端点不认的参数 400 一次后自动摘除（quirk 记忆），主流程不受影响 |

### E. 问一问（/ask，只读问答）的边界

三层递进：**规则直答（0 token）→ agent loop（多步取证）→ 数字接地校验**。边界情况：

| # | 边界情况 | 处理方式 | 用户看到 |
|---|---|---|---|
| E1 | 复合问题被规则层截胡只答一半 | 规则直答只接无参数统计问句：句长 >24 字、含「另外/还有/顺便」等连接词一律放行 agent loop（F1）；复合子问题拆成显式清单注入 goal，每个子问题必须取证（F5） | 多步工具调用 trace 全部可见 |
| E2 | LLM 编造数字 | **数字接地校验**：final 里每个数字必须在某步观察 JSON 里找得到，否则退回模板句拼接（模板句只用真实数据，天然接地）；grounded=false 前端亮黄徽章 | 答案永远可追溯到 ERP 真实值 |
| E3 | 与系统无关的问题（闲聊/天气/常识） | prompt 规则 7：不调工具直接出口说明只答进销存（ask-v4） | 「我只能查本系统的进销存数据…」+ 示例问法 |
| E4 | 输入超长（整段聊天记录贴进来） | 服务端 500 字上限，与录单侧 A15 同口径 | 友好提示拆开问 |
| E5 | 仓库名打多字/错字（「原料仓库」「成品库房」） | 分仓过滤走 `find_depot`（exact + 双向包含模糊，F11 修复）；查无此仓明说并给相近候选 | 「没有叫 X 的仓库，最接近的仓库：…」 |
| E6 | 同名多档案（规格不同） | 与录单同规则：不静默挑第一个，观察里带候选（名字+型号） | 「最接近的档案：螺丝 M8×20 / 螺丝 M10×30，请说明要哪个」 |
| E7 | 问历史单据但原生界面录的单查不到 | `search_history` 只索引经 Talk2Stock 写入的单据（audit.jsonl）——agent 会如实答「历史单据里没有查到」，不会拿原生库数据冒充 | 边界如实告知，不编造 |
| E8 | agent 主数据上下文截断 | 每问只带前 80 条商品名（token 预算）；超出部分靠工具返回的候选兜底 | 不影响工具实测结果 |
| E9 | **主数据/单据超过单页 500 条** | REST 预置工具固定 `pageNo=1&pageSize=500`，超出静默截断——但 F10 已落地 `sql_query` 全库只读查询（服务端聚合，无分页墙），清单/计数/排名类问题已走 SQL 路径；REST 侧翻页循环列为扩展项 | 计数/清单类已不受限，预置工具未触发 |
| E10 | **单据量级增长后的性能** | 三条已落地的服务端路径：官方统计聚合接口（服务端算好）、`sql_query` 全库只读 SQL（GROUP BY/LIMIT 下推数据库）、BM25 检索（进程内）；仍是客户端拉平的只剩分仓聚合表（60s 缓存，O(单据数) 次 HTTP）与欠款账龄——量级上来后迁 SQL，已在扩展路径 | 当前演示规模全部 <10s |

## 三、与提案承诺的对应关系

| 提案原文 | 本设计的落地 |
|---|---|
| "没有人工确认事件的写入请求一律拒绝" | `core/gate.py` 一次性令牌 + 内容哈希绑定（C1–C4） |
| "卡片上每个字段都要标明它的来历" | 已有 / 匹配→X / 将新建 / 系统默认 / 单价? 五种标注 |
| "对出多个候选就列前三个人点" | 匹配失败时给 top3 相似候选（编辑相似度排序），确认卡上点选即重新预览 |
| "只读部分放开让 agent 自己调工具" | `/api/ask`：LLM 选工具 → 只读函数执行 → 依数据作答，页面上答案带数据来源 |
| "审计记录：原话/模型/提示词版本/谁点的确认/改了哪几个字段" | `data/audit.jsonl`，`commit_ok` 事件含全部字段（除确认人，单用户演示版未接登录） |
| "把用户改过的字段自动沉淀成回归测试集" | `data/regression.jsonl`，diff 非空且带原话时自动沉淀 |
