# Talk2Stock 统一 Agent · 答辩与报告素材（2026-11-20）

> 用途：课程报告、PPT、演示脚本。所有数字都来自当前仓库内可复核证据；
> 未跑过的指标不要口头扩展。

## 1. 一句话定位

Talk2Stock 是一个面向真实 jshERP 的统一业务 Agent：用户在同一对话里查经营、
录单、修正草稿、导入图片或表格；Agent 负责理解意图和规划工具，系统负责数字
正确性、草稿校验、人工确认和审计写入。

## 2. 为什么这不是“调用一次大模型”

普通问答/录单：用户输入 → 一次 LLM → 输出结果。

统一 Agent：用户输入 → **理解任务 → 规划 → 调用工具 → 读取观察 → 发现错误/缺项 →
修正计划 → 再行动 → 校验答案/草稿 → 交付**。

闭环里的每一步都有证据：

| 机制 | 代码位置 | 答辩要点 |
|---|---|---|
| Agent 运行时 | `app/core/agent.py` | `{thought, tool, args}` 循环；步数与 token 双预算；决策异常、未知工具、工具异常都会回喂 |
| 回答自我修正 | `app/core/agent.py` | final 含观察外数字先被拦截，作为错误观察要求模型重答；仍失败才模板兜底 |
| 统一业务入口 | `app/core/ask.py` | 查账、录单、澄清、修正同一循环；规则函数退化为工具 |
| 录单校验 | `app/core/billcheck.py` | 草稿出预览前检查库存、历史价、操作员习惯；补丁白名单、只补缺失 |
| 表格修复 | `app/core/repair.py` | Excel 问题行只读取证；高置信自动修、低置信给用户采纳 |
| 写权限边界 | `app/core/gate.py` / `draft.py` | Agent 自主到草稿为止；确认令牌绑定草稿哈希，人工确认后才写入 |

## 3. 可直接放 PPT 的证据页

### 3.1 实测能力

- 库存查询：问「可乐还有多少库存？」→ Agent 调 `stock_query`，回答
  「总库存 52 瓶，全部在成品仓」，grounded=True。
- 经营统计：问「今天卖了多少？」→ Agent 调 `today_stats`，回答 222 元 / 3 单。
- 起草：「从美宜佳买30瓶可乐，单价3块5，入原料仓」→ 草稿金额 105，
  逐单确认令牌生成。
- 会话修正：「改成60瓶，其他不变」→ 保留美宜佳/可乐/3.5/原料仓，
  数量改为 60，金额重算 210。
- 危险请求：「把昨天的单据删掉」→ 不调用草稿工具、不生成草稿，
  明确说明只支持查询和新建草稿。

结果文件：`eval/results/unified_agent_smoke_20261122-045152.json`（5/5）。

## 4. 演示脚本（90 秒）

1. 打开 `/ask`，先问「可乐还有多少库存？」——强调工具调用和接地回答。
2. 再说「从美宜佳买30瓶可乐，单价3块5，入原料仓」——展示草稿卡，不直接写入。
3. 再说「改成60瓶，其他不变」——强调会话状态与修正能力。
4. 打开草稿卡，指出供应商/仓库/商品都有「已有」标签，金额重算 210。
5. 说明：到这一步仍然没写库；只有点击确认、令牌校验、审计后才写入。
6. 如有时间，打开「＋」展示照片与 Excel/CSV；说明它们最终也回到同一草稿卡。

## 5. 可能被问到的问题

**Q：为什么不用更多规则省 token？**
A：确定性函数仍保留为工具，但主入口不再由规则抢跑。Agent 的价值是理解任务、
计划与纠错；数字正确性由工具观察和接地检查保证，而不是由模型自由生成。

**Q：Agent 会不会自己写库？**
A：不会。工具只到草稿；真实写入必须人工确认，令牌绑定草稿哈希，
改过内容必须重新签发，所有写入和拒绝都有审计。

**Q：多规格商品怎么办？**
A：同名多档案不静默选第一条，会返回候选；用户点选后 `material_id` 直达档案，
提交前还有存在性和歧义预检。

**Q：移动端是不是缩水版？**
A：不是。查询、起草、图片、表格、确认卡同一链路；首屏只压缩装饰信息，
不减少核心功能。

## 6. 诚实限制

- 人工实验是 pilot：2 人、16 点、每格 n=2；只能支持方向性结论。
- 当前统一冒烟评测是 5 条核心场景，不等于完整 71 条录单语料复测。
- 图片识别依赖所选模型的视觉能力；本版本入口保留，具体模型不支持时应明确报错。
- 经营看板本次未重构；它的旧交互和样式保持原状。
