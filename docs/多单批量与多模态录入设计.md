# 多单批量 · 多模态 · 表格导入 —— 录入侧升级设计（feature/multi-entry）

> 本分支解决四个评审/用户必问的问题：**一句话多单？拍照录入？任意 Excel 导入？要不要上 agent 多步推理？**
> 结论先行：三个新入口全部收敛到**同一个草稿契约**，决策层/闸门/审计零改动；**不上自主 agent**，
> AI 只出现在三个有界位置（解析抽取、表头映射、有界修复环），其余全是确定性代码。

---

## 一、第一性原理：为什么是「一个契约、三个入口、零新闸门」

录入系统的信任模型只依赖两件事：**写入前有人看过**（确认令牌）和**写入了什么可追溯**（审计）。
多单/图片/Excel 都只是「草稿从哪来」变了——所以：

```
入口 A：一段话（；分单）      ── LLM 抽取（1 次调用出 bills[]）──┐
入口 B：单据照片 ≤4 张       ── 视觉抽取（1 次调用出 bills[]）──┤
入口 C：Excel/CSV ≤500 行    ── AI 认列（≤2 次调用）+ 确定性变换 ┘
                                                                 │
                                              统一契约 bills[]（每单独立令牌）
                                                                 ▼
                        决策层 resolve（三级匹配/歧义候选/风险提醒，原样复用）
                                                                 ▼
                确认（单卡=旧流程 / 多卡=批量预览层 / 行表=导入向导）
                                                                 ▼
              行动层：/api/commit（单张）· /api/commit/batch（逐单过闸门）
```

**闸门不变量在批量语义下的推广**：每张单签发独立的一次性令牌（内容哈希绑定）。
批量提交 = 逐单 `gate.check()`——篡改哪张拒哪张，重放哪张作废哪张，其余照写；
审计逐单一条、`batch_id` 串联。没有引入「批量令牌」这种弱化确认粒度的东西。

## 二、AI 的三个有界位置（以及为什么不上 agent loop）

| 位置 | 输入→输出 | 界限 |
|---|---|---|
| 解析抽取（文本/图片） | 一段话/一张照片 → `bills[]` JSON | 单次调用；输出只许 4 类信息，编号/金额/ID 禁止编造 |
| 表头映射（Excel） | 前 6 行原文+列样本 → 列映射 JSON | 单次调用 + ≤1 轮修复环（失败样本回传重映射，确有改善才采纳） |
| （已有）多轮修正 | 「改成50瓶」→ 修订单张草稿 | 单张语义，不变 |

**不上 agent 的三个硬理由：**
1. **延迟账**：决策步实测 8~28s；多单若逐单跑 agent 循环，20 单要几分钟。批量要的是
   「一次调用抽整批」——恰恰是反 agent 的形状。
2. **安全账**：问一问敢放 agent loop 是因为只读。写路径的自证点（无确认令牌一律拒绝）
   建立在人工确认上；批量确认仍是**一次**人工事件覆盖 N 张单，与闸门完全兼容。
3. **必要性账**：歧义对齐用「候选给人点选」（同名档案绝不静默挑第一个）替代 agent
   自主决策——又便宜又准。AI 不该替人决定把货记进哪个档案。

## 三、性价比与效率（逐项杠杆）

| 杠杆 | 做法 | 效果 |
|---|---|---|
| 图片先压缩再上传 | 客户端 canvas 最长边 1600px / JPEG q0.85（`compressImage`） | 视觉 token 按图片 tile 计费，直接省大头；失败回退原文件 |
| 多图一次调用 | ≤4 张图进同一个 `messages` 请求 | N 张照片 = 1 次 N 单，不逐图跑 |
| 多单一次抽取 | v5 契约 `{"bills": [...]}` | 20 单 1 次调用，文本开销只多一份每单 JSON |
| Excel 行变换零 LLM | 解析/清洗/分组/成草稿全是确定性代码（`core/sheet.py`） | 500 行与 5 行同成本；可单测、可复现 |
| 修复环有界 | 失败行占比 ≥20% 才触发，最多 1 轮，改善才采纳 | LLM 调用上限：2 次/文件 |
| 用量台账 | `parse_image` / `sheet_map` 独立 purpose | 设置页成本卡按用途可见 |

**模型无关性**：档案加 `vision` 能力位（设置页勾选）。图片请求按能力位路由：
当前档案开了 vision 直接用；没开则自动找任意开了 vision 的档案；都没有给可执行指引。
测试用 hy4（免费）、生产换 DeepSeek 视觉版=改档案配置，代码零改动。

## 四、三个入口的边界情况（承接《交互流程与边界情况》编号）

**多单文本（替代旧 A8）**
- M1 「；」分段/句号分段/又买又卖/多往来单位 → bills 多张，字段绝不跨单搬用；
  单笔业务 bills 里只有一张，不硬拆。
- M2 澄清只对单张生效：多单缺信息在确认卡逐单标出（跨单追问会把人绕晕）。
- M3 批量确认层：手机=全屏卡片流+底部粘性操作条；桌面=宽卡片；逐单折叠/展开/改数/换令牌。
- M4 脏单不阻塞整批：改过的单写入前自动 `/api/resolve` 换新令牌；失败单标红留场可改再试。
- M5 顺序提交：前一张补建的主数据必须对后一张立即可见（防同名重复建档），每单成功后清缓存。

**多单附件（合同/发票，选填）**
- 每张单卡片里独立上传（复用 `AttachmentManager`，ERP `/systemConfig/upload` 代理，
  单单 ≤4 份的老限制保持）；`file_name` 随本单写入 DepotHead。
- 解析前在输入区挂的附件属于「整段输入」：多单时提示按单在各卡片上传（v1 不做附件分配器）。

**图片录入**
- V1 手机：`📷` 按钮调起相机/相册；桌面：粘贴截图（Ctrl+V）/拖拽到输入框。
- V2 一张照片多张单：同一次视觉调用直接拆 bills。
- V3 非视觉档案请求图片 → 明确报错并指引去设置页勾选能力位，不静默降级。
- V4 识别结果与文本抽取同一契约、同一确认卡——AI 看错字，人在预览里看得见、改得了。

**表格导入（任意来源，含手工表）**
- S1 不预设模板：AI 看前 6 行猜「表头在哪行、哪列是什么」，人可改每个下拉；重变换零 token。
- S2 表头不在第一行（标题行）→ LLM 给 `header_row`；有单号列多行一单 → `group` 模式聚合。
- S3 缺失分级（仓库人员手工表的真实形态）：
  - 硬缺失（商品名/数量/往来单位）→ 该行「需处理」标红写明缺什么，**不阻塞其他行**；
  - 软缺失（单价→0 元提醒、日期→当前时间、仓库→默认仓）→ 照常进预览，卡上可见可改；
  - 类型列（入库/出库）按 `biz_values` 对照映射，没有就整表默认业务类型。
- S4 脚注行自动跳过（「合计/总计/小计」起头的行）；空行忽略。
- S5 脏值清洗：`¥1,234.5元`/`30瓶`/全角数字/`2024.1.5`/`2024年1月5日`/Excel 序列日期/GBK 编码。
- S6 行级写入：勾选就绪行 → 分块（10/块）顺序提交，进度条+逐行状态回填；失败行带原因留在表里。
- S7 .xls 老格式与超限（>20MB / >500 行）给明确中文指引，不硬解析。

## 五、测试与验证

- `tests/test_bills_parse.py`：三种输出形状兼容、乱输出不炸、v4 规格规则在 v5 不回退、
  澄清仅单张、旧「只处理第一笔」规则确认移除。
- `tests/test_sheet.py`：xlsx(zip+xml) 手工构造解析、CSV 多编码/引号/分号、per_row/group
  变换、缺失分级、脚注行、日期 6 格式+序列值、脏值清洗、映射白名单、修复样本归因。
- `tests/test_gate_batch.py`：令牌按单独立/重放拦截、混合批量（成功+篡改+缺令牌）summary
  与逐单审计落盘、批量上限、视觉消息一次带全图、无视觉档案的指引报错、vision 位保存/继承。
- 全套 `python3 -m unittest discover -s tests`：140 用例（含既有回归）全绿；
  既有 `test_material_match.test_version_bumped` 的版本钉从 v4 更新为 v5（规格规则断言原样通过）。

## 六、已知边界（诚实清单）

- 图片里手写体/严重倾斜的单据识别率依赖视觉模型，兜底是确认卡人工改——不承诺 OCR 精度指标。
- 「解析前附件」在多单场景不自动分配到具体单（提示逐单上传）；附件分配器列为扩展项。
- 导入向导的歧义行（同名多规格）本版直接标「需处理」，点选消歧在确认卡侧完成——
  行内嵌候选点选列为扩展项。
- `sessionStorage` 会话恢复不跨批量刷新保留令牌（令牌 30 分钟本来就会过期，重新预览即换新）。
