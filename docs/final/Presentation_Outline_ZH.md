## 第 1 页 · 标题（0:00–0:10）

**目的**：先给一句话和边界，不先讲架构。

**页面内容**
- Talk2Stock / Conversational ERP Agent。
- 标题：从一句话，到一张可信的单据。
- 副标题：架在真实 ERP 上的对话式业务 Agent。
- 课程、组号、日期。

**讲稿**
“Talk2Stock 用一条对话，把业务一句话变成可核对的草稿，跑在真实 ERP 上；是否写入仍由人确认。接下来用一分钟讲用户和价值，四分钟演示，四分钟讲技术。”

**不要**在这一页放功能清单或架构图。

## 第 2 页 · 目标用户与场景（0:10–1:10）

**目的**：让听众认出用户，并看到两笔隐藏成本。

**页面内容**
- 左侧三类角色：录单员、老板/经营者、仓库/手机。
- 右侧三笔成本：翻译、档案修复、核验。
- 底部：场景 A 主数据齐全；场景 B 缺供应商/商品；同一组四个任务，两种工具。

**讲稿**
“用户不是 ERP 管理员。他知道货到了，但不知道填哪个字段。两笔成本最贵：把一句话翻译成字段，以及发现档案缺失后停下、建档、重来。试点用 A 场景隔离翻译成本，B 场景加入档案修复。S1/S2 共 16 条计时，每格 n=2；这是 pilot，不是显著性研究。”

**视觉**：两栏对比；本页不放图表。

## 第 3 页 · 定位与价值（1:10–2:10）

**目的**：用一分钟说清产品和边界。

**页面内容**
- 定位：真实 ERP 的对话式前台。
- 三个动作：问（只读工具）、起草（可编辑、校验）、确认（一次人工事件、一次性令牌）。
- 价值面板：45.0% / 41.8% 的描述性均值差异；5→0 次中断；注明每格 n=2。
- 边界：不替代 ERP 的控制、权限与账本。

**讲稿**
“Talk2Stock 不是替代 ERP，而是前台：模糊的工作流前段用自然语言，ERP 仍是系统记录。模型可以提议，人负责确认。45% 和 41.8% 是 pilot 方向，不是已证明的加速。”

**避免**：把 45% 说成统计显著或生产结论。

## 第 4 页 · 演示开场：一个对话，三件事（2:10–2:25）

**目的**：在操作前给听众地图。

**页面内容**
- 实际桌面 1440px + 手机 390px 产品图。
- 三个标签：查账、起草、确认。
- 明确可见的“草稿确认后才写入”。

**讲稿**
“一个页面、一个输入框、三种工作。同一个对话在桌面和 390px 手机上都能完成。我先查一个数，再起草并修正一张单，最后一起传两个附件。”

**演示准备**：本地 `http://127.0.0.1:8090/ask`；先 seed；浏览器 100%。首选现场操作，截图是回退。

## 第 5 页 · 演示 1：可追溯的答案（2:25–3:15）

**目的**：证明答案靠数据，不靠模型口才。

**页面内容**
- 用户：“可乐还有多少库存？”
- 轨迹：`stock_query(material="cola") → {total: 52, by_depot: …}`。
- 回答：“52 瓶，全部在成品仓。”
- 三条系统强制：工具选择、数字接地、自我修正。

**现场动作**
1. 输入问题。
2. 展开执行轨迹。
3. 指出观察里的 52 与答案里的 52。

**讲稿**
“模型选工具，但 52 不是模型生成，它在工具观察里。如果 final 出现观察外的数字，回答检查会把它退回模型；确定性模板是最后兜底。”

## 第 6 页 · 演示 2：草稿、修正、确认（3:15–4:35）

**目的**：展示写入边界和会话内修正。

**页面内容**
- 四步：说一句 → 校验 → 修正 → 确认。
- 修正提示：30 → 60 瓶，其他字段保持。
- 实际确认卡截图：60 瓶、￥210。

**现场动作**
1. 说：“从美宜佳买30瓶可乐，单价3块5。”
2. 看草稿卡，再说：“改成60瓶，其他不变。”
3. 展示供应商、商品、价格、仓库不变，合计变 210。
4. 打开确认卡；除非课堂明确要求，不点写入。

**讲稿**
“Agent 只走到草稿。重构保留了上一张草稿，修正只改用户点名的字段。确认卡不是 UI 约定：服务端签发与草稿哈希绑定的一次性 HMAC 令牌，改过就要重新预览、重新签。验收写入 `00000000749`，库存 0→1，随后用受控 seed 回滚。”

## 第 7 页 · 演示 3：多个附件，各有归属（4:35–5:55）

**目的**：证明统一入口不只支持文字。

**页面内容**
- 三个附件：CSV、TXT、图片。
- Agent 为第一份采购、第二份销售分别选择附件。
- 两张草稿：采购 ￥7.00、销售 ￥10.00；各自带附件标签。

**现场动作**
1. 一框选中 CSV 和 TXT。
2. 输入：“第一份是采购，第二份是销售。”
3. 展示两张独立草稿卡与附件名。

**讲稿**
“能本地解析的文件先在本地处理；主模型只拿到压缩目录。多个附件但没有指定归属时，工具拒绝猜测。这是刻意的：Agent 可以规划，但不能悄悄把无关记录合并。”

**回退**：上传慢时，用静态附件图并说明真实测试结果。

## 第 8 页 · 技术历史：四代演进（5:55–6:50）

**目的**：让听众看到最终架构是迭代出来的，不是一次设计。

**页面内容**
- 时间线：交易原型（10–19 Oct）→ Agent 层与评测（24 Oct–9 Nov）→ 专业 Agent（16 Nov）→ 统一边界（19–22 Nov）。
- 底部：93 个提交、两次合并、`feature/unified-agent`。
- 指标：录单历史 98.3%；ask 76.5%→94.1%；专业套件 4/4、4/4、3/3、欠款 15,600=15,600；最终 183 项测试、5/5 冒烟。

**讲稿**
“仓库六周 93 个提交，只有两次合并。每一代都移除了一个假捷径：规则→工具、一次抽取→校验、自由写入→人工令牌、多入口→一个对话。最终分支尚未合入 main，所以这是一个可答辩的最终候选，不是生产宣言。”

**如果问分支策略**：`feature/agent-suite` 已推远端但未并入 main；`feature/unified-agent` 基于它，增加附件、统一 UI 与最终证据。

## 第 9 页 · 技术方案：架构（6:50–7:45）

**目的**：把职责分离讲清楚。

**页面内容**
- 一个入口、四层职责、一道闸门。
- 输入：文本/图片/PDF/Word/Excel/当前草稿。
- 运行时：理解 → 规划 → 工具 → 观察 → 修正 → 收尾。
- 工具：ERP REST、只读 SQL、文档解析、草稿校验、主数据匹配。
- 信任：数字接地 → HMAC 令牌 → 人工确认 → ERP 写入+审计。

**讲稿**
“Agent 只能起草，不能提交。读取走 ERP REST 与只读 SQL；写入只在草稿通过校验、用户确认后走官方建单 API。ERP 源码一行未改。”

## 第 10 页 · 技术方案：Agent 循环（7:45–8:40）

**目的**：回答“这真的是 Agent 吗”。

**页面内容**
- 六步：理解、规划与调用、观察、修正、回答/草稿、检查。
- 预算：步数 + token。
- 轨迹：thought · tool · args · observation。
- 边界：写入停在人工闸门。

**讲稿**
“这不是一次模型调用。每轮只产生一个动作，服务端执行并回喂真实观察。错误、未知工具、缺失字段和歧义候选都是下一轮的正常输入。回答检查可以把未接地 final 退回模型，最后才用确定性兜底。”

**可能的提问**：为什么不用原生 function calling？答：目标端点协议支持参差，手写 JSON 动作循环可移植、可审计、可控制预算。

## 第 11 页 · 技术方案：证据与边界（8:40–9:40）

**目的**：把证据和限制放在同一页，让主张站得住。

**页面内容**
- 试点图：A 88.00→48.45 秒；B 86.48→50.29 秒；45.0%/41.8%；5→0 次中断。
- 证据条：183/183 单测；5/5 统一冒烟；2 文件→2 草稿；0 未确认写入。
- 限制：2 人、每格 n=2、顺序仅部分抵消；5 个核心冒烟不是 71 条全量复测；模型端点是外部依赖。

**讲稿**
“这些是能守住的数字。试点是方向，不是显著性；统一冒烟是 5 个核心行为，不是全量语料；模型端点是外部依赖。最重要的证据是边界：验收写入经过确认，然后由 seed 回滚。我们不宣称生产规模或统计显著。”

## 第 12 页 · 收尾（9:40–10:00）

**页面内容**
- “模型可以不确定。系统不能编造。”

## Q&A 口径

| 问题 | 简短回答 |
|---|---|
| 模型会直接写库吗？ | 不会。起草工具只生成预览；写入是独立的人工确认接口。 |
| 如何防篡改/重放？ | HMAC 令牌绑定草稿哈希 + nonce 黑名单；改数必须重新预览、重签。 |
| 45% 是真的吗？ | 是 2 人、每格 n=2 的 pilot 描述性均值，不是显著性结论。 |
| 为什么不用 RAG？ | 结构化数字需要工具观察和接地；BM25 只用于非结构化检索。 |
| 附件分不清怎么办？ | 工具拒绝猜测，返回目录，Agent 追问或重试。 |
| 还缺什么？ | 统一全量语料、生产鉴权/HTTPS、扫描 PDF OCR、旧版 Office、并发负载。 |
