# jshERP 易用性改造方案

> 目标：在现有 jshERP 前面套一层壳子，让小白也能上手，最大化减少点击。
> 原则：**不改 jshERP 源码**，全部通过 REST API 实现。原系统随时可用作后备。

---

## 一、原系统到底麻烦在哪（实测点击路径）

录一张「从美宜佳买 3 瓶可乐」的采购入库单，在原版 jshERP 里要走：

1. 侧边栏 → 采购管理 → 采购入库 → 点「新增」
2. 供应商下拉 → 找不到「美宜佳」→ **中断，去 基础资料 → 商家信息 → 新增供应商 → 填 8 个字段 → 保存 → 回到单据页重来**
3. 商品行 → 点条码弹窗 → 搜索「可乐」→ 找不到 → **再中断，去 基础资料 → 商品信息 → 新增 → 填分类/单位/规格 → 保存 → 还要建条码 → 回来重选**
4. 填仓库、数量、单价
5. 填单据日期、单据编号、结算账户、本次付款（4 个前端强制必填）
6. 保存 → 审核

**≈ 25 次点击 + 2 次流程中断。** 这正是你说的"点来点去太麻烦"。

壳子里的同一件事：**打一句话 或 填 4 个格子 → 预览 → 确认。约 4 次点击，零中断。**

## 二、已实现（本次交付）

### ✅ 核心机制：主数据"按需自动建"

痛点：*"假如先前没有的供应商客户什么的又要先去新增什么的好麻烦"*

解法：`app/core/draft.py` 的 `resolve()` / `commit()` 两段式。
- `resolve()` 只读匹配，**不写任何数据**，返回 `to_create` 清单（"新建供应商：X"、"新建商品：Y"）
- 用户在预览层看清楚将要创建什么，确认后 `commit()` 才一次性补齐主数据 + 建单

涉及接口：`/supplier/add`、`/material/add`、`/materialsExtend/add`（条码）、`/depot/add`、`/unit/add`

### ✅ 三个入口，一套后端

| 页面 | 地址 | 适合谁 | 依赖 |
|------|------|--------|------|
| 表单快速录入 | `/form` | 日常录单员 | 无（纯预设匹配） |
| AI 智能录入 | `/ai` | 想省事的人 / 手机端 | 需配 LLM |
| 经营看板 | `/dashboard` | 老板 | 无（只读） |

三者共用 `core/draft.py`，**预览确认层完全一致**，不会出现两套逻辑两种行为。

### ✅ 表单页省点击的设计
- 业务类型一排大按钮，点一下切换（原系统要在侧边栏找 6 个不同菜单）
- 往来单位/商品输入框带模糊匹配，**打字时实时提示"⚠ 系统中无此供应商，提交时将自动新建"**
- 明细表格 Tab 键在单元格间跳，最后一行 Tab/Enter 自动加新行 —— 键盘连续录入不摸鼠标
- 单据编号/日期/账户/合计金额全部自动，折叠在「更多选项」里（依据：`docs/字段必填清单.md` 查明这些都可自动生成）
- 写入成功后保留业务类型和往来单位，只清明细 → 连续录同一家的单子很快

### ✅ 出库自动查库存
`resolve()` 对出库类业务自动调 `stock()`，库存不足时预览层橙色提醒
"「牛皮纸」当前库存 0，本次出 50，将产生负库存"。
（jshERP 允许负库存是原设计，我们只提醒不拦截。）

### ✅ 老板看板（全部真实接口，实测数据）
- 本月/今日 采购额·销售额·差额 → `/depotItem/buyIn`、`/saleOut`
- 近 6 个月柱状趋势 → `/depotItem/buyOrSalePrice`
- 库存货值 → `/depotItem/getInOutStockCountMoney`
- 账户总余额 → `/account/getStatistics`
- 待处理单据 / 待收付款 → `/depotHead/waitBillCount`、`/getNeedCount`
- 库存预警（负库存 + 低库存）→ `/material/list` 行自带 `stock`
- 最近单据流水 → `/depotHead/list`（遍历 subType）

## 三、下一步可做（按优先级）

### 🔴 P1 · 操作员视角

| 功能 | 怎么做 | 省掉什么 |
|------|--------|---------|
| **手机扫码录入** | 表单页加 `<input capture>` + 条码库，扫码直接带出商品 | 仓库现场不用回电脑 |
| **一句话查库存** | 复用 `llm.py`，加 query 意图 → `/depotItem/getMaterialDepotStockByParam` | 不用进"库存查询"菜单翻页 |
| **常用单据模板** | 本地存 3~5 个常录组合，一键填充明细 | 重复录同类单据的全部输入 |
| **Excel 批量导入** | 解析 xlsx → 批量走 `resolve/commit` | 月底补录几十张单 |
| **语音输入** | 浏览器 Web Speech API → 直接喂给 `/api/parse` | 手不方便时（搬货中）也能录 |

### 🟡 P2 · 老板视角

| 功能 | 接口 | 价值 |
|------|------|------|
| **每日经营日报推给微信** | `report.official_stats()` + Hermes cron | 不用主动打开系统 |
| **应收应付明细页** | `/depotHead/debtList`（已实测可用） | 谁欠我钱、我欠谁钱一目了然 |
| **毛利真实核算** | 目前"销售−采购"是现金流口径，不是真毛利。需按 `/depotItem/getInOutStock` 的出库成本算 | 老板最关心的数字要准 |
| **滞销品分析** | `/depotItem/getInOutStock` 对比入库时间与出库量 | 压货预警 |
| **供应商比价** | `/depotItem/buyIn` 按 `organId` 分组同一商品单价 | 采购议价依据 |

### 🟢 P3 · 体验

- 单据打印 / 导出 PDF
- 操作撤销（jshERP 有 `batchSetStatus` 反审核）
- 多人协作时的操作日志（`/log/list`）
- PWA 化，手机加到桌面像 App

## 四、口径说明（避免误读数字）

| 指标 | 口径 | 注意 |
|------|------|------|
| 采购额 / 销售额 | `realityPriceTotal`，按**单据明细行**统计 | "笔数"是明细条数不是单据张数 |
| 销售 − 采购 | 现金流差额，**不是毛利** | 备货期为负很正常 |
| 库存货值 | `getInOutStockCountMoney.totalCount` | 按当前成本价估算 |
| 账户余额 | `allCurrentAmount` | jshERP 收付款单不自动改余额，此值靠手工维护 |
| 库存预警 | `material/list` 的 `stock` 字段 | 负库存表示欠货，是 jshERP 原设计 |

## 五、维护提示

```bash
# 起 ERP
cd ~/Desktop/jshERP-suite/jshERP-latest/deploy && docker compose up -d --no-build
# 起壳子
cd ~/Desktop/jshERP-suite/app && python3 server.py 8090
# 自检
cd ~/Desktop/jshERP-suite/app && python3 selfcheck.py
```

接口报 500 时先看真实原因，**不要猜**：
```bash
docker logs erp-backend --since 2m 2>&1 | grep "msg :" | sort -u
```
绝大多数是缺必填参数（详见 `API端点全清单.md` §一）。
